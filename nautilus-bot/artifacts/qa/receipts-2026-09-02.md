# Receipts the ledger lacked (2026-09-02/03)

Parity program item B12.2. The lane's brief asked for seven measurements the
parity ledger was missing, on the condition that every one of them be taken on
a quiet machine — 1-minute load average below about 6 on this 14-core Mac.

**Most of them were not taken, because the machine never went quiet.** What
follows is what was captured, what was not, and exactly why, so the next run
starts from evidence rather than from a second guess.

## Environment

- Hardware: Apple M4 Pro, 14 logical CPUs, 24 GB (25 769 803 776 bytes).
- OS: macOS 27.0 (build 26A5406e).
- Toolchain: rustc 1.93.0 (254b59607 2026-01-19).
- Source: `parity-waves` at `cd3c80c4` plus the lane B12 commits; the packaged
  build below was made at `a84d2abb`.
- Sidecar feature set: the shipped one, `scripts/sidecar-cargo-features.mjs`
  → `--features candle-metal`.
- Fixtures: `scripts/fixtures/local-quality-gate.wav` (5.32 s) and
  `scripts/fixtures/real-speech-44s.wav` (43.97 s) — the same pair the August
  latency receipt and the September 1 acceleration receipt used.

### Machine state, which is the finding

The 1-minute load average was sampled every 90 s from 20:24 on 2026-09-02 to
00:45 on 2026-09-03 while other parity lanes ran `cargo build`, `cargo test`
and `electron-builder`. It never once fell below 25. Observed range: **27 to
279**, on 14 cores. At 00:45 `vm_stat` reported roughly 90 MB of free memory.

That rules out every latency, CPU and resident-memory number in the brief. The
September 1 acceleration receipt already records what happens when these are
taken under contention — a Distil-Whisper process that got paged out returned
numbers 70× worse than the same binary minutes earlier — and repeating that
would add noise to the ledger, not evidence.

### `bun run electron:pack` cannot produce an unsigned build

The brief asked for an unsigned pack. It does not complete:

```
⨯ Packaged native helper verification failed:
  plainsong CLI has no readable entitlement property list
    at readEntitlements (scripts/verify-packaged-native-helpers.mjs:177:5)
    at requireEmptyEntitlements (scripts/verify-packaged-native-helpers.mjs:211:24)
    at Packager.emitAfterPack (app-builder-lib/src/packager.ts:338:5)
```

`electron-builder.yml` sets `hardenedRuntime: true` and `notarize: true`, and
the `afterPack` hook reads each bundled helper's entitlements with
`codesign -d --entitlements`. With `CSC_IDENTITY_AUTO_DISCOVERY=false` — the
way to pack without a signing prompt — electron-builder never signs, so there
is no entitlements plist for the hook to read and the build fails.

The `.app` is still complete when the hook runs, because `afterPack` fires
after the bundle is written. It is ad-hoc linker-signed
(`codesign -dv` → `Signature=adhoc`, `Identifier=Electron`,
`Sealed Resources=none`), carries the correct `com.plainsong.app` identifier
and `0.9.0-beta.3` version, and contains the sidecar, the CLI, and all three
native helpers. That is the bundle `gate:size` measured.

Consequence for the brief's item 4: `bun run gate:packaged:macos:native` is
this same script, so it fails for the same reason on an unsigned pack. It does
not tolerate unsigned, and no receipt for it is claimed here.

Nothing was clicked. No signing identity was requested and no keychain prompt
appeared at any point (`pgrep SecurityAgent` was empty before and after).

### Support bundle, written by the packaged sidecar

Not one of the seven, but it is the evidence behind item B12.1 and it needed no
quiet machine. The packaged `plainsong-sidecar` was driven over its own stdio
JSON-RPC with an empty `PLAINSONG_DATA_DIR`:

- `describe_support_bundle` returned the 9-section list, 5 redaction rules and
  8 exclusions the Settings screen shows.
- `write_support_bundle_privileged` wrote a 5 805-byte zip holding 9 files.
- A relative `targetPath` was refused:
  `targetPath must be an absolute path, got 'relative/path.zip'`.

The log lines handed in were deliberately hostile. Redacted output:

```
[sidecar] ... INFO plainsong_lib::download: staged [redacted:path]
[main] WARN invite mail queued for [redacted:email]
[sidecar] WARN plainsong_lib::llm: provider rejected [redacted:key]
[sidecar] INFO plainsong_lib::asr: [redacted: this line mentioned captured text]
[main] LOG [shortcuts] registered dictation shortcut
```

The first line is what caught a real bug: on the first run it came out as
`[redacted:path] Support/Plainsong/models/base.bin`, because the pattern
stopped at the space in "Application Support" and left the file name behind.
Fixed in `a84d2abb`; the line above is the output after the fix.

## Not captured, and why

| Receipt the brief asked for | Status | Why |
| --- | --- | --- |
| Cold start (`bun run gate:cold-start`) | **not captured** | Timing. Load never below 25; a 2 500 ms threshold is meaningless at load 100+. The packaged app it needs does exist. |
| Dictation stop-to-insert e2e (`artifacts/qa/dictation-latency-e2e.json` + `gate:dictation-latency:e2e`) | **not captured** | Timing. Also note the receipt is gitignored by design (`artifacts/qa/.gitignore` names both dictation-latency JSONs), so it could not have been committed even if taken. |
| Real stop-epoch instrumentation (`dictation_timing.rs`) | **not capturable here** | `DictationTimingRecord` is produced per *live* dictation: a real hotkey release, a real microphone, and real insertion into another app. It is a user-present, on-device step, not something a headless benchmark can drive. `benchmark-latency`'s own receipt says so in `insertionStrategyNote`. |
| Sidecar RSS (idle / 44 s Parakeet / Distil on Metal) | **not captured** | `vm_stat` showed ~90 MB free at the last check. An RSS number taken against a machine that is paging measures the pressure, not the process. |
| Quiet-machine Qwen3-ASR (44 s and 5.3 s) | **not captured** | Timing. `docs/model-inventory-upgrades.md` item 7 and the route tradeoff copy still carry the provisional 11–59 s range, which is correct as written — it explicitly says it is provisional and states a range. |
| whisper `base.en` cold prep (184 ms in Aug vs 14–20 s on Sep 1) | **not captured** | Timing, and this one is the most load-sensitive of the set: the Sep 1 receipt saw 14 261 ms with the features off and 20 409 ms with them on at load 25–33, so the discrepancy is exactly the thing a loaded machine cannot resolve. Hypothesis remains the Metal shader cache; unproven. |
| As-shipped sidecar latency for the acceleration receipt | **not captured** | Timing. The blocker the Sep 1 receipt predicted did *not* recur: `benchmark-latency` was rebuilt through `scripts/cargo-sidecar.mjs` with the shipped feature set (sha256 `974ac43f…02eb`) and staged, and no keychain prompt appeared. Only the load stopped it. |
| Idle CPU with the call-detection poll on vs off, 60 samples | **not captured** | CPU percentage over a 60-sample window is the single most load-sensitive number in the list. |
| `gate:packaged:macos:native` | **fails on unsigned** | See above; the gate requires an entitlements plist that an unsigned pack does not have. |
| `qa:packaged:macos:idle-cpu` | **not captured** | Same reason as the idle-CPU re-baseline. |

## What the next run needs

Everything above except the two `dictation_timing.rs` items is a re-run away.
The pieces are staged and do not need rebuilding:

- `release/mac-arm64/Plainsong.app` (ad-hoc signed, at `a84d2abb`).
- A `benchmark-latency` built with the shipped feature set, sha256
  `974ac43fd0bc4eaba7a0c9e5b0bb63ea6aaa31d6cc02bf9f590717f5194902eb`.
- An isolated `PLAINSONG_DATA_DIR` with `whisper`, `parakeet`,
  `distil_whisper`, `qwen3_asr` and `bundled_cleanup` symlinked in.

The two scripts that drive the whole set are kept with the session scratchpad
rather than committed, because they hardcode this machine's paths.

The one number that cannot come from a re-run of a script is the real
stop-to-insert latency. That needs somebody at the Mac: hold the dictation
shortcut, speak, release, and read the `DictationTimingRecord` the sidecar logs.
