# Fix Dictation: Transcription, Clipboard, and Cursor Insertion

## Issues Identified

### 1. Transcription Returns "you" (Critical Bug)
**Root Cause**: Stereo/Mono channel mismatch in audio capture.

In `audio.rs`:
- `start_dictation()` captures audio from the default input device
- If the device is stereo, samples are captured as L,R,L,R,... interleaved
- `stop_dictation()` calls `encode_wav(&samples, sample_rate, 1)` - **hardcodes 1 channel**
- WAV file has `channels=1` in header but contains interleaved stereo data

In `utils.rs`:
- `load_wav_file()` reads WAV header, sees `channels=1`
- Does NOT convert stereo-to-mono (only triggers if `channels == 2`)
- Audio is played at 2x speed, pitch shifted - garbled audio
- Whisper interprets garbled audio as "you" or nonsense

### 2. Clipboard Copy Not Working
**Possible causes**:
- `pbcopy` command may fail silently
- No error propagation to UI

### 3. Cursor Insertion Not Working
**Root Cause**: macOS Accessibility permissions required for CGEvent keyboard simulation.

The code at `lib.rs:4896-4915` uses `CGEvent` to simulate Cmd+V, which requires the app to have Accessibility permissions. The error message indicates this but may not be shown to the user clearly.

## Fix Plan

### Fix 1: Audio Channel Handling in `audio.rs`

**File**: `nautilus-bot/src-tauri/src/audio.rs`

1. Track the number of channels during dictation capture
2. Convert stereo to mono during capture (preferable) or before encoding

**Changes**:
```rust
// In AudioCapture struct (add field)
dictation_channels: u16,

// In start_dictation() - capture channel count
let channels = config.channels();
self.dictation_channels = channels;

// In the capture callbacks - convert stereo to mono inline:
// For stereo: average L and R samples
// For mono: pass through

// In stop_dictation() - pass actual channel count to encode_wav
// OR convert to mono before encoding
```

**Alternative simpler fix**: Always request mono input stream configuration or convert stereo to mono after capture.

### Fix 2: Clipboard Error Handling

**File**: `nautilus-bot/src-tauri/src/lib.rs`

Add better logging and ensure clipboard errors are visible:
- Log when `copy_to_clipboard()` succeeds/fails
- Ensure `paste_error` is propagated to UI

### Fix 3: Accessibility Permission Check

**File**: `nautilus-bot/src-tauri/src/lib.rs`

Before attempting paste, check if Accessibility is granted:
- Use `get_permission_diagnostics()` to check accessibility status
- Show clear error if permissions missing
- Emit event to frontend to show permission request dialog
